# 功能点推进表

**编号即顺序，也即提交序。** 一个编号 = 一次提交 = 一份功能文档
（`docs/features/NNNN-<slug>.md`）。编号一旦使用就不再复用。

推进原则：**先做能被机器验证的，再做需要 GPU/摄像头的。** 因此 core 层
（不需要 Godot、不需要 GPU）排在最前面，它承担了全项目大部分的单元测试。

## 说明

- **0000–0009（除 0003）是 core 层**：全部可在任意机器上 `zig build test` 验证，
  不依赖 Godot、GPU 或摄像头。这一段结束时，播放逻辑的正确性已经被测试锁死，
  后面的平台代码只剩"把数据搬对"这一件事。
- **0003 是提前插入的 GDExtension 骨架**：它不产出 core 逻辑，只把工具链钉死
  （绑定生成、清单、引擎加载、GDScript 绑定）。提前的理由见 0003 的功能文档。
- **0010–0012 是解码层**：`decode-smoke` 让"解码能不能跑"与"Godot 里能不能出画"
  两件事解耦，前者可以进 CI。
- **0013–0017 是呈现层**：每平台一个功能点，每个都要在真实机器上验证一次。
- **0018–0021 是集成与交付**：接线已在 0003 打好，这一层是把功能填进去。
