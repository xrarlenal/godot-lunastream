## 这个功能点做了什么

立起一个可以立刻跑测试的空仓库：`build.zig` + `src/core/` 能被 `zig build test`
构建并通过，同时把"一个功能点 = 代码 + 单元测试 + 功能文档 + 一次提交"的约定
写进 `docs/CONTRIBUTING.md`，供后续所有功能点遵循。

## 为什么现在做

后续每个功能点都要有可验证的落脚点。先把 `test` 步骤打通，从第一次提交起就有
绿灯基线，后面任何一个功能点让测试变红都能立刻定位到是哪次提交引入的。

## 实现要点

- **core 与 Godot 解耦**：`src/core/` 不引用任何 Godot 或平台 SDK 类型，因此它的
  单元测试不需要引擎、不需要 GPU、也不需要目标平台。这是本仓库最重要的结构性
  决定——它让绝大部分逻辑可以在任意机器上验证。
- 优化模式显式声明默认值（`ReleaseSafe`）而不是用 0.16 的
  `standardOptimizeOption`，避免本地与 CI 的默认值不同导致测试表现不一致。
- GDExtension 构建目标**暂不接入**：它需要 gdzig 绑定与 Godot 头文件
  （约 50 MB 的下载与生成步骤），在没有对应功能点之前引入只会拖慢每次 `zig build test`。

## 单元测试覆盖了什么

| 测试 | 锁定的行为 |
|---|---|
| `core 模块可以编译并被引用` | core 模块根可被构建与引用，`version` 非常量空串 |
| `core 模块可以编译并被引用`（refAllDecls） | 模块内所有声明都能通过语义分析（防止只写不用的死代码） |

## 验证方式与结果

```bash
zig build test
```

结果：全部通过（2 个测试）。
