## 这个功能点做了什么

core 有了**表面生命周期保险**：`RetireRing(N)` 让每块解码表面在呈现之后停满
N 个渲染帧再释放，且恰好释放一次。同时写好了它依赖的类型擦除回调
`VoidClosure`（上下文指针 + 函数指针），后面帧的 `release_hook` 与解码后端接口
都用它。

## 为什么现在做

这是全项目**唯一防止 use-after-free 的机制**，而它恰好是纯逻辑——不碰 Godot、
不碰 RenderingDevice、不碰任何平台类型。守内存安全的东西最需要被测试锁死，
又最容易被写成"只有真机上才能发现问题"，所以优先把它做成可单测的一层。

它和 0002 的帧队列是一对：队列负责"这帧交给谁"，回收环负责"这块内存什么时候
才能还回去"。队列满时丢弃的帧也必须立刻交给回收环（不能直接 `release`），
否则丢帧反而变成 use-after-free。

## 实现要点

### 为什么不用 GPU fence

三平台各有一套围栏（Metal `MTLSharedEvent`、D3D12 `ID3D12Fence`、Vulkan
semaphore），语义各不相同，而它们要防的误差只有一两帧。用一条有界环按帧计数，
代价是"延迟固定为 N 帧"，收益是这一层变成 200 行纯逻辑、可跨平台单测。

**这个取舍有代价，必须写清楚**：N 取得太小就不再安全。N 的取值要在呈现管线
那一步按 Godot 的帧延迟上界定，不能拍脑袋。

### 时序契约：每帧先 advance 再 retain

| 调用 | 作用 |
|---|---|
| `advance()` | 老化一帧：释放"已活过 N 帧"的那个槽位 |
| `retain(hook)` | 把本帧的表面停进当前写槽位 |

顺序反了会少停一帧（等于 N 的实际值变成 N-1）。这条契约写在类型注释里，
调用点只有一处（呈现管线），由那一处保证。

### 先清槽，再回调

`releaseSlot` 先把槽位置空再调用闭包。这样即使闭包内部又碰到这个环（重入），
也不会把它自己二次释放。这不是理论顾虑——释放闭包会走回解码池的归还逻辑。

### drain 的顺序与幂等

`drain()` 从"下一次 advance 会复用的槽位"开始走，因此释放顺序与稳定态老化
一致（最旧优先）。它必须幂等：停止播放和销毁通道都会调它，重复调不能双重释放。

### 有界性由测试锁死

环的容量恰好是 N，所以稳定态下**呈现路径上零堆分配**。有一条测试专门跑 200 帧，
断言"同时停放的表面数从不超过 N"——它防的是"实现里不小心加了无界缓冲"这类
回归，而不是当前的实现。

### `isEmpty()` 而不是直接读字段

源码里到处写 `slot.func != null`。读代码的人得先知道 `func` 字段的含义才能
判断意图，所以加了一个语义化的 `isEmpty()`，字段比较只留在这一处。

## 单元测试覆盖了什么

| 测试 | 锁定的行为 |
|---|---|
| `空闭包的 call 是安全空操作` | 空值忽略语义 |
| `闭包携带上下文并被调用` | 上下文指针传递与多次调用 |
| `只给函数不给上下文时，回调仍被调用并收到 null` | `ctx == null` 不等于"没有回调" |
| `表面恰好停放 N 帧后释放一次` | 核心契约：N 帧、恰好一次、之后不再释放 |
| `延迟为 1 时下一帧即释放` | N=1 的边界 |
| `每帧各停一块时按 FIFO 顺序释放，且各恰好一次` | 20 帧连停 + drain，顺序与唯一性 |
| `稳定态下同时停放的表面数不超过 N（有界，不随帧数增长）` | 无界缓冲回归 |
| `drain 释放全部且幂等` | 停止/销毁路径 |
| `deinit 释放未到期的表面（没有泄漏）` | 析构不漏 |
| `空闭包被接受且不占槽位` | 没有原生表面的帧（如测试帧） |
| `latencyFrames 如实报告配置值` | 上报值可被上层信任 |

## 已知限制 / 下一步

- **N 的取值未定**：要按 Godot 的帧延迟上界确定，属于呈现管线那一步的工作。
  在那之前它只是一个可配置参数。
- **不做 fence 校验**：没有"GPU 真的读完了"的确认，靠帧数上界覆盖。若将来出现
  平台级花屏问题，这里是要重新审视的第一处。
- 下一步（0005）：呈现选择器（drop-late / hold-early）——决定"这一帧该在什么
  时候上屏、还是直接丢掉"，它和本模块同属每帧节拍上的一环。
