# NNNN · 功能点名称

| 项 | 值 |
|---|---|
| 提交 | `<commit subject>` |
| 日期 | YYYY-MM-DD |
| 阶段 | P0 / P1 / P2 / P3 |
| 依赖 | 前置功能点编号，或"无" |

## 这个功能点做了什么

一段话说清这次提交新增/改变了什么行为。不要写"修改了某某文件"，要写
"现在具备了什么能力"。

## 为什么现在做

依赖顺序上的理由：它被谁依赖、不做会不会挡住后面的功能点。

## 实现要点

关键设计取舍与容易踩的坑。如果有与源工程不同的做法，在这里写明差异与原因。

## 单元测试覆盖了什么

逐条列出测试名与它锁定的行为。测试名要能当规格读。

## 验证方式与结果

跑过的命令与实际输出（通过数/失败数），以及手工验证的步骤与观察结果。

## 已知限制 / 下一步

这次没做的、以及为什么可以不做；以及紧接着的下一步是什么。
